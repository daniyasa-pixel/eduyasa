## Kontrak identitas dan urutan
- ID bab, soal, modul, nama file, referensi media, progres, riwayat, level, bintang dan evaluasi lama tidak boleh diganti/di-reset akibat perubahan urutan.
- ID bab baru menggunakan nomor berikutnya yang belum dipakai untuk mapel/kelas; tidak memakai B01A untuk bab sisipan. Sufiks a pada nama paket soal lama bukan identitas bab.
- Contoh BIN-B05: MOD-01 dan MOD-02 pada ID BIN-B05-MOD-01/02; soal BIN-B05-M01-001 dst. Jumlah soal mengikuti CONTENT_GUIDE.md dan keputusan produksi.
- Metadata katalog yang dibaca aplikasi harus memisahkan chapter_id, title, semester, display_order, source/profile dan status ketersediaan. Semester tidak diketahui boleh null. Bab kandidat/pending tidak boleh dapat dipilih sebelum materi dan bank tersedia.
- Contoh sisipan B01, B05, B02: urutan layar 1,2,3 tetapi identitas tetap B01,B05,B02. Urutan cukup diubah pada metadata; path bank dan ID diambil dari identitas permanen, bukan indeks array atau urutan tampilan.
- Profil prioritas LKS semester 1 menampilkan urutan tabel di atas. Konten tambahan tetap bisa dipilih untuk latihan; jangan diam-diam memasukkannya ke bank latihan semester LKS tanpa keputusan pemetaan. Semester 2 belum ditetapkan dari foto.
- Bila isi lama sepenuhnya memenuhi bab LKS, gunakan pemetaan ID lama/alias tampilan yang tepat. Bila tumpang tindih sebagian, manfaatkan yang relevan dan tambah kekurangan. Hindari duplikasi soal saat menggabungkan latihan; jangan memindahkan atau menomori ulang ID lama.
- Satu sumber katalog yang konsisten untuk frontend web dan Android; saat ini Android masih memakai nomor chapter sebagai identitas dan SemesterPresentation memakai ambang nomor bab. Refaktor satu kali untuk menggunakan ID/nomor internal stabil. Audit pemilihan, pemuatan materi/bank, pengacakan, laporan, statistik, penyimpanan progres dan batas jumlah pilihan unit. Uji regresi urutan sisipan, pemilihan semester dan kompatibilitas riwayat sebelum rilis.
